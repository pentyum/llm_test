# P5b 系统已知局限性与工程演进说明 (KNOWN_LIMITATIONS.md)

## 1. 硬件与环境局限

1. **单卡 8GB 显存瓶颈**：
   RTX 4060 Laptop 具备 8188 MiB VRAM。在运行 7B MoE 模型时，Backbone 参数与 KV Cache 占用了主要显存空间，留给动态专家缓存的显存上限约在 128~256 MiB 之间。这要求专家缓存必须具备高度精细的字节级回收能力。
2. **Linux Page Cache 缓冲效应**：
   在频繁访问热点专家时，操作系统文件缓存会自动驻留在部分主机内存中。我们通过区分逻辑文件读取（`logical_read_bytes`）与物理块设备读取，在报告中明确标注为 `buffered` 模式，不伪造为物理冷盘 NVMe 访问。

## 2. 软件与算法局限

1. **非原生 INT4 Tensor Core GEMM**：
   当前 INT4 执行路径为 GPU 内矢量化解包反量化为 BF16，再由 Tensor Core 执行矩阵乘法。虽然比旧版 CPU 解包加速了近 50 倍，但相较原生 INT4/FP4 硬件指令，仍存在约 0.5 ms 的解包显存带宽开销。未来 P6 阶段若集成 Triton/CUTLASS 融合 INT4 GEMM 内核，将进一步消除该开销。
2. **多层替换范围**：
   本阶段严格验证了 L1 [0]、L2 [0, 4] 与 L4 [0, 4, 8, 12] 四个关键层的高效协同。全量 16 层的完全卸载由于需要对整模型其余 12 层进行全量参数解耦，可在后续阶段持续演进。
